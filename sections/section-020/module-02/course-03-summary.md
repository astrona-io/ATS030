# Summary

A request depends on discovery, selected capacity, port mapping and permitted network access before application behavior can be evaluated. A Running Pod is only one observation within that chain.

Diagnosis identifies the first demonstrated failure and changes that relationship deliberately. Routing correction cannot repair incompatible application configuration, and permitted transport cannot prove the requested operation is authorized or correct.

A focused request diagnosis identifies the first unresolved boundary from the affected caller. Correct selection, target-port mapping and ready endpoints are necessary facts, while the original application operation supplies end-to-end verification.
